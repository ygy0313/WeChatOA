# 变更记录规范

本目录存放该工程**每一次需求改动的完整记录**。一份改动 = 一份 md 文件，不合并、不省略。

## 文件命名

```
YYYY-MM-DD-<改动简述>.md
```

同日多次改动加序号：`2026-10-11-新增选题库.md`、`2026-10-11-调整发布节奏.md`。

## 必须包含的章节

| 章节 | 内容 |
|---|---|
| 元信息 | 日期、类型（feat/fix/refactor/docs/chore）、提交号 |
| 需求描述 | 这次要解决什么问题，为什么做 |
| 改动清单 | 表格：文件 / 变更类型 / 说明 |
| 关键决策 | 为什么这么写，放弃了什么方案 |
| 验证方式 | 怎么确认是对的 |
| 风险与遗留 | 已知限制、未完成项 |

## 模板

复制下面这段新建文件即可：

```markdown
# <改动标题>

- **日期**：YYYY-MM-DD
- **类型**：feat / fix / refactor / docs / chore
- **提交**：`<git hash>`

## 一、需求描述

（这次要解决什么，背景是什么）

## 二、改动清单

| 文件 | 变更 | 说明 |
|---|---|---|
| `xxx.md` | 修改 | …… |

## 三、关键决策

- 决策一：……（理由）

## 四、验证方式

- [ ] 验证项一

## 五、风险与遗留

- ……
```

## 约定

- 每次改动一份记录，保证内容与记录一一对应。
- 改动完成后同步更新工程根目录的 `MEMORY.md` 时间线。
